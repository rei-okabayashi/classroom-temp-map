# データ契約 v1 — 教室の温度ムラ「見える化」

- 状態：**企画者承認済み・v1確定（2026-08-10）→ Day 0（8/17）でメンバーに説明**
- これは「ノード ⇄ 集約M5Stack」の**約束事**です。ここさえ揃っていれば、4人が並列で作っても最後に必ず合流できます。
- **「v1」の v はバージョン（版番号）のことです。** 資料の「第1版・第2版」と同じで、いまは第1版なので v1 です。**ルールを変えたいときは、必ずチームで合意してから版番号を1つ上げます**（v1→v2。勝手に項目を足しません）。こうすると、新旧のルールが混ざっても「どの版で作られたデータか」を区別できます。
- このファイル（`docs/data-contract.md`）が正本です。
- ノードとは、教室に置く測定係の小さなコンピューターです（ESP32＋温湿度センサーのセット）。M5Stackとは、画面つきの小型マイコンで、教壇でデータを受け取る集約役です。

## 1. 全体のルール

| 項目 | 決め | つまりこういうこと |
|---|---|---|
| 送信周期 | **30秒に1回** | 各ノードは電源が入ってから30秒おきに測って送ります。ノードどうしで送るタイミングを合わせる必要はありません |
| 通信方式 | ESP-NOW **ユニキャスト** | ESP-NOW＝WiFiルーターなしでESP32どうしが直接データを飛ばせる無線のしくみです。ユニキャスト＝「その場の全員に向かって叫ぶ」のではなく、**宛先を1台決めて送る**方式です。宛先は集約役のM5Stackです |
| 宛先の指定 | M5Stackが起動画面に自分のMACアドレスを表示 → 各自が `config.h` に書き写します | MACアドレス＝機器1台ごとに工場出荷時から付いている固有の番号（**機器の住所**のようなもの）です。`config.h`＝各ノードのプログラムの中にある設定ファイルです。書き写しは8/17週の放課後に行います（初期タスクの13番です） |
| チャンネル | **1に固定** | チャンネル＝無線の通り道の番号です（トランシーバーの「チャンネルを合わせる」と同じです）。送る側と受ける側が同じ番号になっていないと届きません |
| 暗号化 | なし | 暗号化＝通信の中身を他人に読めなくする処理です。ここを流れるのは温度と湿度だけで個人情報がないので、設定が簡単な「なし」を選びます |
| 送信失敗時 | 「届いたよ」の返事がなければ**1秒後に1回だけ再送**。それでもダメなら諦めて次の周期に任せます | しつこく再送しないのは、30秒後にはどうせ次の測定データが来るからです。1回分くらい欠けても分析には響きません（欠けたこと自体は下の `seq` で分かります） |
| 時刻 | **ノードは時計を持ちません**。データが届いた瞬間に、M5Stackが自分の時計で時刻を付けます | 時計を持つのは集約M5Stackの1台だけです。ノード4台の時計をぜんぶ合わせる手間をなくすための決めです |

## 2. 送る中身（ノード → 集約）

データは **JSON（ジェイソン）** という書き方で送ります。JSONは「`項目名:値`」をカンマで並べる、機械が読み間違えないための書き方です。見た目は暗号っぽいですが、読み方は簡単です。

正常時に送るのはこの1行です：

```json
{"v":1,"id":"n1","seq":123,"t":26.4,"h":55.2}
```

日本語にすると——**「契約の版は1。私はノードn1。これは起動してから123回目の送信。気温26.4℃、湿度55.2%」**です。

センサーの読み取りに失敗したときは、気温・湿度の代わりに `err` を入れて送ります：

```json
{"v":1,"id":"n1","seq":124,"err":"sensor"}
```

日本語にすると——**「契約の版は1。私はノードn1。124回目の送信。センサーの読み取りに失敗した」**です。

### 各項目の意味

| 項目名 | 入る値 | いつ入れる | 意味 |
|---|---|---|---|
| `v` | 整数（いまは必ず `1`） | 毎回 | この契約の**版番号（バージョン）**です。受け取る側はこの数字で「どの版のルールで作られたデータか」を見分けます。ルール変更でv2になったら、更新前のノードのデータ（`v:1`）が混ざっても区別できます |
| `id` | 文字（`"n1"`〜`"n4"`） | 毎回 | **ノードの名前**です。どのノード（＝どの場所）の測定かを表します。各ノードの `config.h` に固定で書き込みます。名前と設置場所の対応表はREADMEで管理します |
| `seq` | 整数（0から+1ずつ） | 毎回 | **通し番号**です。送信のたびに1ずつ増えます。受け取った側で番号が飛んでいたら（例：123の次が125）「途中の1回が電波の途中で消えた」と分かります。ノードを再起動すると0に戻って構いません |
| `t` | 数値（小数1桁） | 正常時のみ | **気温（℃）**です。センサーSHT31が返した生の値をそのまま送ります（ズレの補正は集約側の仕事です。ノードでは何もしません） |
| `h` | 数値（小数1桁） | 正常時のみ | **湿度（%）**です |
| `err` | 文字 | 失敗時のみ | `"sensor"`＝センサー読み取り失敗の印です。**失敗しても黙らずに送る**のがポイントで、「何も送ってこない＝ノードごと止まっている」と「errを送ってくる＝ノードは生きていてセンサーだけ故障」を見分けられます（生存報告を兼ねます） |

- **この6個以外の項目を勝手に足しません**。足したくなったらチームで合意 → 版番号を上げます（v1→v2）。
- 1回分のデータは約60バイトです。ESP-NOWが一度に送れる上限（250バイト）の1/4以下なので余裕は十分です。

## 3. 集約側の記録（SDカード・CSV）

- CSV＝**カンマ区切りの表形式ファイル**です。Excelやスプレッドシートでそのまま開けます。
- ファイルはSDカードの `/LOG.CSV` です。**1件受け取るたびに1行追記して、その場でSDカードへの書き込みを確定させます**（＝突然電源が切れても、消えるのは最大1行だけです）。
- **CSVには生の値を記録します**。追加の校正（＝基準の温度計と並べて測ってセンサーごとのズレを調べること）は実施しません。SHT31は出荷時に個体ごとの校正が済んでおり、手元で用意できる精度の温度計を基準にするとかえって誤差が増えるためです（`docs/presentation-outline.md` の想定問答3に詳しく書いてあります）。そのため補正値は設定していません（プログラム上のオフセットは4台とも0のままです）。**画面表示・CSV・分析のすべてが生値で統一されています**。どこかの段階だけ値が違う、ということは起きません。

列の並び：`recv_time,clock,node_id,seq,temp_c,hum_pct,status`

| 列 | 意味 |
|---|---|
| `recv_time` | M5Stackがそのデータを**受け取った時刻**（例 `2026-08-21 10:30:15`） |
| `clock` | `set`／`unset`。M5Stackの時計が**設定済みかどうかの印**です。`unset` の間の `recv_time` は仮の時刻なので、分析のときは除外するか後で手補正します |
| `node_id` `seq` `temp_c` `hum_pct` | 送られてきた中身の書き写しです（`err` のときは `temp_c` `hum_pct` を空欄にします） |
| `status` | `ok`＝正常／`sensor_err`＝センサー読み取り失敗 |

例（2行目がセンサー失敗の例）：

```csv
2026-08-21 10:30:15,set,n1,123,26.4,55.2,ok
2026-08-21 10:30:22,set,n3,98,,,sensor_err
```

日本語にすると——1行目は「8/21 10:30:15にノードn1の123回目の送信を受信。気温26.4℃・湿度55.2%で正常」、2行目は「n3の98回目はセンサー読み取り失敗」という意味です。

## 4. 画面表示の目安（参考。契約ではない）

- ノードごとに：最新の気温・湿度＋最後に受信してからの経過秒数を表示します。
- **90秒（3周期）以上データが来ないノードは「無応答」と表示します**。
- 時刻未設定の間は画面に「時刻未設定」警告を常時表示します。
