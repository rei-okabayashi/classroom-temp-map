# データ契約 v1 — 教室の温度ムラ「見える化」

- 状態：**ドラフト（2026-08-01）→ 企画者承認で確定 → Day 0（8/17）でメンバーに説明・承認**
- これは「ノード ⇄ 集約M5Stack」の約束事。ここさえ揃っていれば、4人が並列で作っても最後に必ず合流できる。
- **変更したいときは必ずチームで合意してから `v` を上げる**（勝手にフィールドを足さない）。
- リポジトリに入れる際は `docs/data-contract.md` に置く。

## 1. 全体のルール

| 項目 | 決め |
|---|---|
| 送信周期 | **30秒に1回**（ノード起動時から。厳密な同期は不要） |
| 通信方式 | ESP-NOW **ユニキャスト**（宛先＝集約M5StackのMACアドレス） |
| 宛先MACの配り方 | M5Stackが起動画面に自分のMACを表示 → 各自が `config.h` に転記 |
| チャンネル | **1に固定**（送受で揃える） |
| 暗号化 | なし（個人情報を含まない環境データのため。設定の単純さを優先） |
| 送信失敗時 | 送達確認NGなら**1秒後に1回だけ再送**。それでもダメなら諦めて次の周期に任せる |
| 時刻 | **ノードは時計を持たない**。時刻は受信した瞬間にM5Stackが付ける |

## 2. ペイロード（ノード → 集約、JSON文字列）

正常時：

```json
{"v":1,"id":"n1","seq":123,"t":26.4,"h":55.2}
```

センサー読み取り失敗時（`t` `h` は省略し、代わりに `err`）：

```json
{"v":1,"id":"n1","seq":124,"err":"sensor"}
```

| フィールド | 型 | 必須 | 意味 |
|---|---|---|---|
| `v` | int | ✔ | スキーマ版数。いまは `1`。互換を壊す変更で +1 |
| `id` | string | ✔ | ノードID `"n1"`〜`"n4"`。各ノードの `config.h` に固定。設置場所との対応表はREADMEで管理 |
| `seq` | int | ✔ | 起動からの通番（0開始・+1ずつ）。**欠落（パケットロス）の検出用**。再起動で0に戻ってよい |
| `t` | number | 正常時✔ | 気温 ℃・小数1桁。**SHT31の生値**（校正補正は集約側で） |
| `h` | number | 正常時✔ | 相対湿度 %・小数1桁 |
| `err` | string | 異常時のみ | `"sensor"`＝読み取り失敗。生存報告を兼ねる（無送信＝ノード停止と区別できる） |

- 上記以外のフィールドを**勝手に足さない**（足したくなったら合意 → `v` を +1）。
- サイズは約60バイト。ESP-NOW上限250バイトに対して十分な余裕。

## 3. 集約側の記録（SDカード・CSV）

- ファイル：`/LOG.CSV` に追記（1受信＝1行）。**1行ごとにフラッシュ**（電源断でも欠損は最大1行）。
- **CSVは生値を記録**する。校正オフセット（8/25の並走で決定）は別管理とし、表示・分析時に適用する（生データを汚さない）。

列：`recv_time,clock,node_id,seq,temp_c,hum_pct,status`

| 列 | 意味 |
|---|---|
| `recv_time` | 受信時刻 `2026-08-21 10:30:15`（M5Stackの時計） |
| `clock` | `set`／`unset`。`unset`＝時刻未設定中（この間の `recv_time` は仮値。分析時に除外か手補正） |
| `node_id` `seq` `temp_c` `hum_pct` | ペイロードの転記（`err` 時は `temp_c` `hum_pct` を空欄） |
| `status` | `ok`／`sensor_err` |

例：

```csv
2026-08-21 10:30:15,set,n1,123,26.4,55.2,ok
2026-08-21 10:30:22,set,n3,98,,,sensor_err
```

## 4. 画面表示の目安（参考。契約ではない）

- ノードごとに：最新の気温・湿度＋最終受信からの経過秒。
- **90秒（3周期）以上受信が無いノードは「無応答」表示**。
- 時刻未設定の間は画面に「時刻未設定」警告を常時表示。
