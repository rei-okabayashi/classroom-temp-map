# Windows 11 環境構築手順

このリポジトリ（`classroom-temp-map`）でファームウェアを書き込めるようにするための、Windows 11 向けセットアップ手順です。IT経験がなくても、上から順番にやれば完了する粒度で書いています。わからない用語が出てきても、書いてある通りにクリック・入力すれば大丈夫です。

**対象者**：ノード担当（全員）＋ 集約表示オーナー（M5Stack担当）
**所要時間の目安**：初回は1〜2時間（esp32ボードパッケージのダウンロードに時間がかかるため）
**前提**：Windows 11（64bit）、インターネット接続、自分のPCの管理者権限（ドライバインストールで必要になることがあります）
**用意するもの**：USBケーブル（データ通信対応のもの。充電専用ケーブルは使えません）、自分の担当ボード（ノード担当は ESP32-DevKitC-32E、集約担当は M5Stack Basic）

手順は次の8ステップです。集約担当だけに必要なステップには「（集約担当のみ）」と書いてあります。それ以外は全員共通です。

---

## 1. Arduino IDE 2.x のインストール

1. 公式サイト [https://www.arduino.cc/en/software/](https://www.arduino.cc/en/software/) を開く。
2. 「Windows」向けのダウンロードボタンを探す（現行バージョンは **Arduino IDE 2.3.10**。サイトを開いた時点でこれより新しいバージョンが表示されていたら、そちらをダウンロードして問題ありません）。ファイル名の目安は `arduino-ide_2.3.10_Windows_64bit.exe`。
3. 「Just Download」（無料）をクリックしてダウンロード。寄付を求める画面が出ますが、支払わなくても下の方に無料ダウンロードのリンクがあります。
4. ダウンロードした `.exe` をダブルクリックしてインストール。表示される画面はすべて既定値のままで進めてOK（ライセンス同意 → インストール場所 → インストール実行）。
5. インストール後、Arduino IDE を一度起動して、画面が開くことを確認する。

> 補足：このインストーラーは USB ドライバも一部まとめて入れてくれることがあります。まず手順3（USBドライバ）の「確認」だけ先にやってみて、デバイスマネージャーに `COM` 番号が出ていれば、そのステップの手動インストールは不要です。

---

## 2. ボードマネージャーURLの追加 → esp32パッケージ 3.3.11 のインストール

1. Arduino IDE を開き、左上メニューの `ファイル`（File）→ `基本設定`（Preferences）を開く（ショートカット `Ctrl+,` でも可）。
2. 「追加のボードマネージャのURL」（Additional boards manager URLs）の欄に、以下のURLを貼り付ける。

   ```
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```

   すでに他のURLが入っている場合は、改行またはカンマ区切りで追記する（上書きしない）。

3. 「OK」をクリックして設定画面を閉じる。
4. 左側の縦アイコンの中から「ボードマネージャ」（Boards Manager、四角が積み重なったアイコン）をクリック。
5. 検索欄に `esp32` と入力すると、「**esp32 by Espressif Systems**」が出てくる。
6. バージョン選択のドロップダウンから **3.3.11** を選び、「インストール」（Install）をクリック。

   **これは数百MB〜1GB以上のダウンロードになるため、環境によっては10〜30分ほどかかります。** インストール中はPCの電源とネット接続を切らないでください。途中で止まっているように見えても、進捗バーが動いていれば待ってOKです。

7. インストール完了後、一覧に `esp32 (3.3.11)` と表示されていれば成功。

---

## 3. USBドライバのインストール

### 3-1. ノード用（ESP32-DevKitC-32E）＝ CP210x ドライバ（全員）

1. ESP32-DevKitC-32E をUSBケーブルでPCに接続する。
2. `Windowsキー` を右クリック →「デバイスマネージャー」を開く。「ポート (COM と LPT)」の項目を確認する。
   - すでに `Silicon Labs CP210x USB to UART Bridge (COMx)` のように表示されていれば、ドライバは入っているのでこのステップは完了。次（3-2または手順4）に進んでOK。
   - 何も表示されない／「ほかのデバイス」に「!」マーク付きで出ている場合は、以下の手動インストールに進む。
3. 公式サイト [https://www.silabs.com/software-and-tools/usb-to-uart-bridge-vcp-drivers](https://www.silabs.com/software-and-tools/usb-to-uart-bridge-vcp-drivers) を開く。
4. 「Downloads」タブから、Windows向けの VCP ドライバ（zip）をダウンロードする。
5. ダウンロードしたzipを右クリック →「すべて展開」で解凍する。
6. 解凍したフォルダの中から `CP210xVCPInstaller_x64.exe`（64bit Windows 11用）を実行し、インストールを進める。
7. インストール後、PCの再起動を求められたら再起動する。
8. もう一度デバイスマネージャーの「ポート (COM と LPT)」を確認し、`Silicon Labs CP210x USB to UART Bridge (COMx)` が出ていればOK。この `COMx` の番号は手順7で使うのでメモしておく。

### 3-2. 集約用（M5Stack Basic）＝ CH9102 または CP2104（集約担当のみ）

M5Stack Basic は製造時期によって、USB通信用のチップが **CH9102** または **CP2104** のどちらかになっています（見た目では区別できません）。まず上の3-1と同じ手順で CP210x ドライバをインストールした状態でM5Stack Basicを接続し、デバイスマネージャーに `COM` 番号が出るか確認してください。

- **出た場合**：CP2104チップです（CP210xドライバでカバーされます）。追加作業は不要。
- **出ない／認識されない場合**：CH9102チップです。M5Stack公式ドキュメント [https://docs.m5stack.com/en/download](https://docs.m5stack.com/en/download) のドライバ配布ページから CH9102 用ドライバ（Windows用インストーラ）をダウンロードして実行し、案内に従ってインストールしてください。インストール後、再度デバイスマネージャーで `COM` 番号が出るか確認します。

## 4. M5Unified ライブラリのインストール（集約担当のみ）

ノード担当は追加ライブラリ不要のため、このステップは飛ばしてOKです。

1. Arduino IDE の左側の縦アイコンから「ライブラリマネージャ」（本のアイコン）を開く。
2. 検索欄に `M5Unified` と入力する。
3. 「**M5Unified** by M5Stack」を選び、「インストール」をクリック。
4. 依存ライブラリ（M5GFXなど）を一緒にインストールするか聞かれたら「Install All」を選ぶ（M5UnifiedはM5GFXに依存しており、自動で入ります）。
5. インストール完了後、ライブラリ一覧に `M5Unified` が表示されていればOK。

---

## 5. リポジトリの clone（Git for Windows + VSCode）

1. **Git for Windows** を公式サイト [https://git-scm.com/download/win](https://git-scm.com/download/win) からダウンロードし、インストールする。インストール画面はほぼすべて既定値のままでOK（「Git from the command line and also from 3rd-party software」が選ばれている状態が既定です。変更不要）。
2. **VSCode（Visual Studio Code）** を公式サイト [https://code.visualstudio.com/download](https://code.visualstudio.com/download) からダウンロードし、インストールする（Windows x64 User Installer、管理者権限不要のもので問題ありません）。
3. VSCode を開き、メニュー `ターミナル`（Terminal）→ `新しいターミナル`（New Terminal）でターミナルを開く。
4. リポジトリを置きたい場所（例：`ドキュメント` フォルダ）に移動してから、以下のように clone する。

   ```
   git clone <リポジトリのURL> classroom-temp-map
   ```

   > 【要確認】このリポジトリはまだGitHub上に作成されていません（2026-08-01時点）。実際の clone URL はリポジトリ作成後にチームへ共有します。それまでは、共有されたURLをこの `<リポジトリのURL>` の部分に入れて実行してください。

5. clone が終わったら、VSCode の `ファイル`（File）→ `フォルダーを開く`（Open Folder）で、clone してできた `classroom-temp-map` フォルダを開く。

---

## 6. node-template を開いて検証（コンパイル）する

1. **Arduino IDE** を開く（VSCodeではなくArduino IDEを使う）。
2. `ファイル`（File）→ `開く`（Open...）で、clone した `classroom-temp-map` フォルダの中の `firmware/node-template/node-template.ino` を開く。
3. 上部メニューの `ツール`（Tools）→ `ボード`（Board）→ `esp32` の中から「**ESP32 Dev Module**」を選択する。
4. 画面左上のチェックマークのアイコン（検証/コンパイル）をクリックする。
5. 下側の出力ウィンドウに赤いエラーが出ず、最後に「コンパイルが完了しました」（Done compiling）「スケッチが使用しているプログラム領域は...」のようなメッセージが出れば成功。

初回はコンパイルに数分かかることがあります（手順8のトラブルシュートも参照）。

### 集約担当のみ：gateway も検証する

1. 同じ手順で `firmware/gateway/gateway.ino` を開く。
2. `ツール`（Tools）→ `ボード`（Board）→ `esp32` の中から「**M5Core**」を選択する（M5Stack Basic用のボード設定）。
3. 検証（コンパイル）が通ることを確認する。手順4の M5Unified が入っていないと `M5Unified.h: No such file or directory` エラーになるので、その場合は手順4に戻る。

---

## 7. 実機への書き込みとシリアルモニタでの確認

1. ESP32-DevKitC-32E をUSBケーブルでPCに接続する（手順3-1のドライバが入っている状態）。
2. `ツール`（Tools）→ `シリアルポート`（Port）から、手順3-1でメモした `COMx` を選択する。
3. 画面左上の右矢印アイコン（マイコンボードに書き込む／Upload）をクリックする。
4. 出力ウィンドウに `Hard resetting via RTS pin...` や `Leaving...` のようなメッセージが出て、赤いエラーなく終われば書き込み成功（うまくいかない場合は手順8の表を参照）。
5. `ツール`（Tools）→ `シリアルモニタ`（Serial Monitor）を開く（虫眼鏡アイコン、または `Ctrl+Shift+M`）。
6. シリアルモニタ画面の右下にある通信速度のドロップダウンを **115200 baud** に合わせる。
7. 以下のような出力が表示されれば、書き込みと動作確認は完了です。

   ```
   === onmura node ===
   NODE_ID=n1  schema v1
   my MAC: xx:xx:xx:xx:xx:xx
   ```

   このあと30秒ごとに `send ok` または `send FAIL` の行が出ますが、この時点では **`send FAIL` や `add_peer failed` が出ても異常ではありません**。まだ `config.h` の `GATEWAY_MAC` を実際の集約M5StackのMACアドレスに書き換えていないためです（この書き換えは、各自が `firmware/nodes/n1` などにコピーして作業する段階で行います）。ここでは「シリアルにログが出続けている＝ボードが正常に動いている」ことだけ確認できればOKです。

### 集約担当のみ：M5Stackへの書き込み確認

1. M5Stack Basic をUSBケーブルで接続し、`ツール` → `シリアルポート` でM5Stack側のCOM番号を選ぶ（手順3-2でドライバ確認済みの前提）。
2. ボードが「M5Core」になっていることを確認して、`firmware/gateway/gateway.ino` を書き込む。
3. シリアルモニタ（115200 baud）に以下が出て、M5Stackの画面下部にも同じMACが表示されればOK。

   ```
   === onmura gateway ===
   MAC: xx:xx:xx:xx:xx:xx
   ```

   この **MACアドレスが、各ノードの `config.h`（`GATEWAY_MAC`）に転記する値** になります。SDカード未挿入だと画面に `SD NG` と出ますが、環境構築の確認としてはこの時点では問題ありません。

## 8. トラブルシューティング

| 症状 | 主な原因 | 対処 |
|---|---|---|
| デバイスマネージャーに COM ポートが出てこない | USBドライバが入っていない／ケーブルが通信非対応 | 手順3を再確認。ケーブルを別のものに替えてみる（下の「充電専用ケーブル」も参照） |
| 書き込み（Upload）でエラーになる・失敗する | ボードが書き込みモードに入れていない | ボード上の **BOOT**（または **G0**）ボタンを見つけ、Upload実行と同時に長押しし、「Connecting...」の表示が出たらボタンを離す。ESP32-DevKitC-32Eは通常は自動で書き込みモードに入るが、うまくいかない基板では有効な回避策 |
| 書き込み中に応答がない／PCがケーブルを認識しない | 充電専用USBケーブルを使っている | データ通信線が入っていない安価なケーブルは書き込みに使えない。スマホのデータ転送用ケーブルなど、他の用途でファイル転送に使ったことがあるケーブルに替える |
| シリアルモニタに文字化けや無反応が出る／書き込み先を間違えている | ポート選択の間違い（別のCOM番号を選んでいる、他のUSB機器と混同） | `ツール` → `シリアルポート` の一覧を開き直し、ボードを一度抜き差ししてから増えたCOM番号を選び直す。PCに複数のUSBデバイスを挿している場合は要注意 |
| ボードマネージャでesp32パッケージのインストール・コンパイルがとても遅い | 初回はダウンロード量が多い／PCのスペックやネット回線 | 初回のesp32パッケージインストールと初回コンパイルは特に時間がかかるのが普通（数分〜数十分）。フリーズしたように見えても進捗バーやログが動いていれば待つ。何十分も完全に無反応なら一度Arduino IDEを再起動して再試行 |

---

困ったときは、自己判断で強引に進めず、企画者に状況（どの手順で・どんなメッセージが出たか）を伝えて相談してください。
