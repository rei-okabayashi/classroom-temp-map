## ラベル

| ラベル | 用途 |
|---|---|
| `node` | 各ノード（ESP32-DevKitC-32E）側の実装・配線・確認。ノードとは教室に置く測定係の小さなコンピューターのことで、ESP32-DevKitC-32E（無線通信ができる小型マイコン。マイコン＝プログラムで動く小さなコンピューター）＋温湿度センサーのセットです（n1〜n4の4台） |
| `gateway` | 集約（M5Stack Basic）側の実装・確認。集約とは4台のノードからデータを受け取ってまとめる係のことで、M5Stack Basicは画面つきの小型マイコンです |

## M1: Day 0 完了（8/17）

### 1. Arduino IDE 2.x をインストールする
- ゴール: 各自のPCに Arduino IDE 2.x を入れ、起動できることを確認します。
- ラベル: `ops`
- マイルストーン: M1
- 目安時間: 30分

### 2. ESP32 ボードマネージャを登録する
- ゴール: 環境設定に `https://espressif.github.io/arduino-esp32/package_esp32_index.json` を登録し、`esp32:esp32` core 3.3.11 をボードマネージャからインストールします。このURLはESP32のボード情報の入手先で、登録するとArduino IDEがESP32ボードを扱えるようになります。
- ラベル: `ops`
- マイルストーン: M1
- 目安時間: 20分

### 3. 担当ボードの USB ドライバをインストールする
- ゴール: ノード担当は CP210x ドライバ、集約担当は使用する M5Stack Basic の世代に応じて CH9102 または CP2104 ドライバを入れ、PCがボードをCOMポート（PCがUSB機器と会話するための接続口の番号。COM3など）として認識することを確認します。
- ラベル: `ops`
- マイルストーン: M1
- 目安時間: 15分

### 4. GitHub アカウントを作成しリポジトリをクローンする
- ゴール: 各自 GitHub アカウントを用意し、`classroom-temp-map` リポジトリ（プロジェクト一式の保管場所。フォルダごと、変更履歴つきで置いておく場所）をローカルにクローン（GitHub上のリポジトリを自分のPCへ丸ごと複製すること）します。
- ラベル: `ops`
- マイルストーン: M1
- 目安時間: 20分

### 5. VSCode + Git 拡張の動作を確認する
- ゴール: VSCodeでリポジトリを開き、変更のステージ（次のコミットに入れる変更を載せておく準備台）・コミット（変更内容の記録。ゲームのセーブポイントのようなもの）がGUI（マウスで操作できる画面）でできることを確認します（GitHub Desktopは使わない運用です）。
- ラベル: `ops`
- マイルストーン: M1
- 目安時間: 15分

## M2: 1週目の製作〜中間デモ①（8/21）

Day 0（放課後45〜60分）で完了できるのは上のタスク5までです。ここから下は8/17週の放課後・自宅作業で進め、8/21の中間デモ①（企画者機＋最低1台のメンバー機のデータが集約に届いている状態）をゴールにします。

### 6. node-template を nodes/n1 にコピーしID設定する
- ゴール: `firmware/node-template` を `firmware/nodes/n1/n1.ino` としてコピーし、`config.h` の `NODE_ID` を `"n1"` にします。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 7. node-template を nodes/n2 にコピーしID設定する
- ゴール: 同上の手順を n2 で行います（フォルダ名とinoファイル名を一致させます）。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 8. node-template を nodes/n3 にコピーしID設定する
- ゴール: 同上の手順を n3 で行います。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 9. node-template を nodes/n4 にコピーしID設定する
- ゴール: 同上の手順を n4 で行います。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 10. AE-SHT31 にピンヘッダをはんだ付けする
- ゴール: 担当ノード分のAE-SHT31（温度と湿度を測るセンサー部品の型番）にピンヘッダをはんだ付けします（1人1枚）。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 30分

### 11. SHT31 をノードに配線する
- ゴール: ESP32-DevKitC-32E に SHT31 を配線します（3V3 / GND / SDA=GPIO21 / SCL=GPIO22）。デフォルトI2Cアドレス0x45で動くことを前提にします。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 12. gateway スケッチを M5Stack Basic に書き込み起動確認する
- ゴール: `firmware/gateway/gateway.ino`（スケッチ＝Arduinoでのプログラムファイルの呼び名）を M5Stack Basic（ボード種別: M5Core）に書き込み（コンパイル＝書いたプログラムを機械が実行できる形に変換し、文法ミスがないか確かめること。書き込み＝コンパイルしたプログラムをUSBケーブル経由でボードに転送すること）、起動画面に自分のMACアドレス（機器1台ごとに工場出荷時から付いている固有の番号。機器の住所のようなもの）が表示されることを確認します。
- ラベル: `gateway`
- マイルストーン: M2
- 目安時間: 30分

### 13. gateway の MAC アドレスを各ノードの config.h に転記する
- ゴール: タスク12で確認したMACアドレスを、n1〜n4それぞれの `config.h` の `GATEWAY_MAC` に1バイトずつ転記します。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 15分

### 14. ノードの送信をシリアルモニタで確認する
- ゴール: 各ノードを書き込み・起動し、30秒周期でJSON（「項目名:値」をカンマで並べる、機械が読み間違えないためのデータの書き方。`{"v":1,"id":"n1","seq":...,"t":...,"h":...}`）がシリアルモニタ（マイコンが出すメッセージをPCの画面で見るための窓）に出力されることを確認します。「契約の版は1。私はノードn1。seqは通し番号、tは気温、hは湿度」の形式です。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 30分

## M3: 2週目・全ノード稼働〜中間デモ②（8/24〜8/28）

2週目は「測る」週です。8/25（火）目安で全ノード稼働＋校正並走、8/26（水）から教室に常設して記録を始めます。8/28（金）の中間デモ②は「常設記録のCSVをSQLite（ファイル1つで使える小さなデータベース。訓練校で学習済み）で読めている状態」がゴールです。

### 15. gateway での受信をシリアルモニタで確認する（n1〜n4）
- ゴール: 4台のノードそれぞれからの受信をgateway側のシリアルモニタで確認します。
- ラベル: `gateway`
- マイルストーン: M3
- 目安時間: 30分

### 16. microSD を FAT32 フォーマットして gateway に挿す
- ゴール: 用意したmicroSDカード（16GB以下・Class10）を FAT32（SDカードの標準的な記録形式）でフォーマット（＝SDカードを初期化してその形式に整えること）し、M5Stack Basicに挿して認識を確認します。
- ラベル: `gateway`
- マイルストーン: M3
- 目安時間: 15分

### 17. SD への LOG.CSV 書き込みを確認する
- ゴール: 受信のたびに `/LOG.CSV` に1行追記され、電源を切っても直前までの行が残っていることを確認します（記録は1行ごとにフラッシュ＝書き込み待ちのデータをその場でSDカードに確定させる方式なので、突然電源が切れても消えるのは最大1行だけです）。
- ラベル: `gateway`
- マイルストーン: M3
- 目安時間: 20分

### 18. 時刻設定（TIMEコマンド）の手順書を書いてチームに共有する
- ゴール: シリアルで `TIME 2026-08-17 09:00:00` のように送って時刻を設定する手順と、常時通電で保持されること、未設定中は画面警告＋CSVの`clock`列が`unset`になることをdocsにまとめます。あわせて「その日PCやケーブルが教室に無い場合」に備え、教壇のM5Stack付近に予備USBケーブルを常備し、時刻設定に使えるPCの当てを決めておきます（停電・電源断のたびに再設定が必要になるためです）。
- ラベル: `docs`
- マイルストーン: M3
- 目安時間: 30分

### 19. README 役割表を更新する
- ゴール: Day 0で決まった担当者名・ノードIDと設置場所の対応を README の役割表に反映します（担当名はGitHubユーザー名で記入します。本名は書きません）。
- ラベル: `docs`
- マイルストーン: M3
- 目安時間: 15分

### 20. 設置場所と電源を決めて設置する
- ゴール: 各ノードと集約の設置場所（教室内の詳細位置は公開リポジトリに書きません）と電源（コンセントかモバイルバッテリーか）を決め、実際に設置します。
- ラベル: `ops`
- マイルストーン: M3
- 目安時間: 30分

### 21. 校正並走を実施し CAL_OFFSET_T を決める
- ゴール: 基準となる温湿度計とノードの値を並走させて比較する校正（キャリブレーション＝基準になる温度計と並べて測り、センサーごとのズレを調べること）を行い、`firmware/gateway/config.h` の `CAL_OFFSET_T`（表示用オフセット＝校正で分かったズレの補正値、℃）を決めます。SDのCSVには生値（センサーが返した値を補正せずそのまま記録したもの）のまま記録し続けるため上書きしません。**決めるだけで終わらせません**: 決めた値をconfig.hに書いてPR（Pull Request。「この変更を本体に取り込んでください」という提案。チームの誰かが確認してから取り込みます）を出し、企画者レビュー→マージ（提案された変更を本体に取り込むこと）後、教壇のM5Stackへ実際に再書き込みし、再起動後にTIMEコマンドを再送して画面の時刻と校正後の表示値を確認するところまでがこのタスクの完成です（担当: 集約表示オーナー＋企画者）。
- ラベル: `analysis`
- マイルストーン: M3
- 目安時間: 45分
- 【要確認】基準に使う温湿度計（機種・保有の有無）は共有事実に無いため未確定です。

### 22. CSV から最初のグラフを1枚作る
- ゴール: `/LOG.CSV` を取り込み、ノードごとの気温推移がわかるグラフを1枚作ります。分析担当が習っているSQLiteの活用を軸に、具体的なツール（表計算ソフトか、SQLite＋グラフツールか）は分析担当と相談して決めます。
- ラベル: `analysis`
- マイルストーン: M3
- 目安時間: 45分
- 【要確認】可視化に使う具体的なソフト・ライブラリは共有事実に無いため未確定です。

### 23. 常設運用の開始チェックリストを作り実行する
- ゴール: 時刻設定の再確認・SD空き容量・電源・設置固定・校正値（CAL_OFFSET_T）の実機反映が完了しているか・READMEの最終更新など、8/26（水）の常設記録開始前に確認する項目をチェックリスト化し、実行します。日常の見回りとデータ回収の手順は `docs/first-boot-check.md` を土台にします。
- ラベル: `ops`
- マイルストーン: M3
- 目安時間: 30分
