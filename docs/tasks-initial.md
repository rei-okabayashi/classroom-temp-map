### 6. node-template を nodes/n1 にコピーしID設定する
- ゴール: `firmware/node-template` を `firmware/nodes/n1/n1.ino` としてコピーし、`config.h` の `NODE_ID` を `"n1"` にします。
- 手順（Windowsのエクスプローラーで行います。n2〜n4の人は `n1` を自分の番号に読み替えてください）:
  1. `firmware/node-template` **フォルダごと**コピーします（右クリック →「コピー」）。中の `node-template.ino` と `config.h` の2つが一緒に移動する必要があります。
  2. `firmware` の下に `nodes` フォルダが無ければ作り、その中に貼り付けます。
  3. 貼り付けたフォルダの名前を `node-template` から **`n1`** に変更します。
  4. その中の `node-template.ino` の名前を **`n1.ino`** に変更します（`config.h` は名前を変えません）。
  5. `n1/config.h` をテキストエディタ（VSCodeなど）で開き、`#define NODE_ID "n1"` の部分を自分の番号にします。
  - **※Arduino IDEは「フォルダ名」と「.inoファイルの名前」が同じでないとスケッチを開けません。** `n1` フォルダの中は必ず `n1.ino` にしてください。ここを間違えると、開こうとしたときにエラーになります。
  - ※共通の雛形である `firmware/node-template` は**書き換えずに残します**（次の人がコピー元として使うためです）。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 13. gateway の MAC アドレスを各ノードの config.h に転記する
- ゴール: タスク12で確認したMACアドレスを、n1〜n4それぞれの `config.h` の `GATEWAY_MAC` に1バイトずつ転記します。
- 書き方（画面に出る形と、ファイルに書く形が違うので注意してください）:

  ```
  【M5Stackの画面・シリアルに出る表示】
  MAC: 24:0A:C4:12:34:56

  【config.h に書く形】
  static const uint8_t GATEWAY_MAC[6] = {0x24, 0x0A, 0xC4, 0x12, 0x34, 0x56};
  ```

  やることは3つだけです。①コロン `:` をカンマ `,` に変える ②2文字ずつの前に `0x` を付ける ③全体を `{ }` で囲む。
  書けたら数えてください。**`0x` が6個、カンマが5個**あれば正しい形です。アルファベット（A〜F）は大文字でも小文字でも同じです。
  ※上の `24:0A:C4:12:34:56` は書き方の例です。実際の値はタスク12で確認した自分たちのM5Stackのものを使ってください。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 15分

### 21. 校正並走を実施し CAL_OFFSET_T を決める 【中止】

**このタスクは実施しないことにしました。**理由は「時間がなかったから」ではなく、**実測して不要だと分かったから**です。

常設記録のうち、誰もいない休日（空調停止・人の出入りなし）の5,741件で4台を突き合わせたところ、**台どうしの差は最大でも0.18℃**でした。今回見たい差（授業時間の平均1.9℃・最大4.3℃）の10分の1以下なので、補正を入れても結論は変わりません。

もう一つの理由は、**やると精度が下がる**ことです。SHT31は出荷時に個体ごとの校正が済んでいるセンサーです（Sensirion公式データシート SHT3x-DIS 2022年12月・Version 7 の図1の説明文に *factory calibrated* と明記）。カタログ精度は温度 typ. ±0.2℃。これを校正し直すには、基準にする温度計のほうが十分に正確でなければ意味がありません。ところが手元で用意できる市販の温度計はほとんどが ±1℃程度で、±0.2℃のSHT31より粗いです。それを基準にオフセットを決めると、**基準器側の誤差をこちらに持ち込むだけ**になります。下の【要確認】（基準に使う温湿度計が未確定）は、結果的にこの判断で解消しました。

これに伴い、画面表示・CSV・分析のすべてを生値に統一しています。`firmware/gateway/config.h` の `CAL_OFFSET_T` は**全ノード `0.0f` のまま**なので、実際にはどこにも補正は掛かっていません。定数そのものを消す作業は、集約M5Stackへの再書き込みが必要になるため、**常設記録が終わってから**行います。発表での説明は `docs/presentation-outline.md` の想定問答3にまとめてあります。
