## M1: Day 0 完了（8/17）

### 1. Arduino IDE 2.x をインストールする
- ゴール: 各自のPCに Arduino IDE 2.x を入れ、起動できることを確認する。
- ラベル: `ops`
- マイルストーン: M1
- 目安時間: 30分

### 2. ESP32 ボードマネージャを登録する
- ゴール: 環境設定に `https://espressif.github.io/arduino-esp32/package_esp32_index.json` を登録し、`esp32:esp32` core 3.3.11 をボードマネージャからインストールする。
- ラベル: `ops`
- マイルストーン: M1
- 目安時間: 20分

### 3. 担当ボードの USB ドライバをインストールする
- ゴール: ノード担当は CP210x ドライバ、集約担当は使用する M5Stack Basic の世代に応じて CH9102 または CP2104 ドライバを入れ、PCがボードをCOMポートとして認識することを確認する。
- ラベル: `ops`
- マイルストーン: M1
- 目安時間: 15分

### 4. GitHub アカウントを作成しリポジトリをクローンする
- ゴール: 各自 GitHub アカウントを用意し、`classroom-temp-map` リポジトリをローカルにクローンする。
- ラベル: `ops`
- マイルストーン: M1
- 目安時間: 20分

### 5. VSCode + Git 拡張の動作を確認する
- ゴール: VSCodeでリポジトリを開き、変更のステージ・コミットがGUIでできることを確認する（GitHub Desktopは使わない運用）。
- ラベル: `ops`
- マイルストーン: M1
- 目安時間: 15分

## M2: 1週目の製作〜中間デモ①（8/21）

Day 0（放課後45〜60分）で完了できるのは上のタスク5まで。ここから下は8/17週の放課後・自宅作業で進め、8/21の中間デモ①（企画者機＋最低1台のメンバー機のデータが集約に届いている状態）をゴールにする。

### 6. node-template を nodes/n1 にコピーしID設定する
- ゴール: `firmware/node-template` を `firmware/nodes/n1/n1.ino` としてコピーし、`config.h` の `NODE_ID` を `"n1"` にする。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 7. node-template を nodes/n2 にコピーしID設定する
- ゴール: 同上の手順を n2 で行う（フォルダ名とinoファイル名を一致させる）。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 8. node-template を nodes/n3 にコピーしID設定する
- ゴール: 同上の手順を n3 で行う。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 9. node-template を nodes/n4 にコピーしID設定する
- ゴール: 同上の手順を n4 で行う。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 10. AE-SHT31 にピンヘッダをはんだ付けする
- ゴール: 担当ノード分のAE-SHT31にピンヘッダをはんだ付けする（1人1枚）。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 30分

### 11. SHT31 をノードに配線する
- ゴール: ESP32-DevKitC-32Eに SHT31 を配線する（3V3 / GND / SDA=GPIO21 / SCL=GPIO22）。デフォルトI2Cアドレス0x45で動くことを前提にする。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 20分

### 12. gateway スケッチを M5Stack Basic に書き込み起動確認する
- ゴール: `firmware/gateway/gateway.ino` を M5Stack Basic（ボード種別: M5Core）に書き込み、起動画面に自分のMACアドレスが表示されることを確認する。
- ラベル: `gateway`
- マイルストーン: M2
- 目安時間: 30分

### 13. gateway の MAC アドレスを各ノードの config.h に転記する
- ゴール: タスク12で確認したMACアドレスを、n1〜n4それぞれの `config.h` の `GATEWAY_MAC` に1バイトずつ転記する。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 15分

### 14. ノードの送信をシリアルモニタで確認する
- ゴール: 各ノードを書き込み・起動し、30秒周期でJSON（`{"v":1,"id":"n1","seq":...,"t":...,"h":...}`）がシリアルモニタに出力されることを確認する。
- ラベル: `node`
- マイルストーン: M2
- 目安時間: 30分

## M3: 2週目・全ノード稼働〜中間デモ②（8/24〜8/28）

2週目は「測る」週。8/25（火）目安で全ノード稼働＋校正並走、8/26（水）から教室に常設して記録開始。8/28（金）の中間デモ②は「常設記録のCSVをSQLiteで読めている状態」がゴール。

### 15. gateway での受信をシリアルモニタで確認する（n1〜n4）
- ゴール: 4台のノードそれぞれからの受信をgateway側のシリアルモニタで確認する。
- ラベル: `gateway`
- マイルストーン: M3
- 目安時間: 30分

### 16. microSD を FAT32 フォーマットして gateway に挿す
- ゴール: KIOXIA KCA-MC016GS 16GB を FAT32 でフォーマットし、M5Stack Basicに挿して認識を確認する。
- ラベル: `gateway`
- マイルストーン: M3
- 目安時間: 15分

### 17. SD への LOG.CSV 書き込みを確認する
- ゴール: 受信のたびに `/LOG.CSV` に1行追記され、電源を切っても直前までの行が残っている（1行ごとにフラッシュされている）ことを確認する。
- ラベル: `gateway`
- マイルストーン: M3
- 目安時間: 20分

### 18. 時刻設定（TIMEコマンド）の手順書を書いてチームに共有する
- ゴール: シリアルで `TIME 2026-08-17 09:00:00` のように送って時刻を設定する手順と、常時通電で保持されること、未設定中は画面警告＋CSVの`clock`列が`unset`になることをdocsにまとめる。
- ラベル: `docs`
- マイルストーン: M3
- 目安時間: 30分

### 19. README 役割表を更新する
- ゴール: Day 0で決まった担当者名・ノードIDと設置場所の対応を README の役割表に反映する（担当名はGitHubユーザー名で記入。本名は書かない）。
- ラベル: `docs`
- マイルストーン: M3
- 目安時間: 15分

### 20. 設置場所と電源を決めて設置する
- ゴール: 各ノードと集約の設置場所（教室内の詳細位置は公開リポジトリに書かない）と電源（コンセントかモバイルバッテリーか）を決め、実際に設置する。
- ラベル: `ops`
- マイルストーン: M3
- 目安時間: 30分

### 21. 校正並走を実施し CAL_OFFSET_T を決める
- ゴール: 基準となる温湿度計とノードの値を並走させて比較し、`firmware/gateway/config.h` の `CAL_OFFSET_T`（表示用オフセット、℃）を決める。SDのCSVには生値のまま記録し続けるため上書きしない。
- ラベル: `analysis`
- マイルストーン: M3
- 目安時間: 45分
- 【要確認】基準に使う温湿度計（機種・保有の有無）は共有事実に無いため未確定。

### 22. CSV から最初のグラフを1枚作る
- ゴール: `/LOG.CSV` を取り込み、ノードごとの気温推移がわかるグラフを1枚作る。分析担当が習っているSQLiteの活用を軸に、具体的なツール（表計算ソフトか、SQLite＋グラフツールか）は分析担当と相談して決める。
- ラベル: `analysis`
- マイルストーン: M3
- 目安時間: 45分
- 【要確認】可視化に使う具体的なソフト・ライブラリは共有事実に無いため未確定。

### 23. 常設運用の開始チェックリストを作り実行する
- ゴール: 時刻設定の再確認・SD空き容量・電源・設置固定・READMEの最終更新など、8/26（水）の常設記録開始前に確認する項目をチェックリスト化し、実行する。
- ラベル: `ops`
- マイルストーン: M3
- 目安時間: 30分
