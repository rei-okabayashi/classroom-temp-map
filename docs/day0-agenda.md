## 3. Git一周演習の手順

目的：`day0/<自分のハンドル>.md` を新規作成して自己紹介を1行書き、ブランチ作成→commit→push→PR作成→企画者レビュー→マージ、を全員が1周する。

`<handle>` は各自のGitHubユーザー名など、他の人と被らない短い文字列に置き換える。

```bash
# 1. リポジトリの最新化（ローカルにclone済みの前提）
git checkout main
git pull

# 2. 自分用のブランチを作る
git checkout -b day0/<handle>

# 3. ファイルを作る（VSCodeで day0/<handle>.md を新規作成し、自己紹介を1行書いて保存）
#    例: 「n1担当の◯◯です。よろしくお願いします。」

# 4. 変更をステージしてコミット
git add day0/<handle>.md
git commit -m "day0: <handle>の自己紹介を追加"

# 5. リモートにpush
git push -u origin day0/<handle>
```

続けてブラウザ側の操作：

1. push後にターミナルへ出るURL（またはGitHub上のリポジトリページ）を開き、「Compare & pull request」からPRを作成する。
2. PRの説明欄（`.github/pull_request_template.md` のテンプレート）に沿って、やったことを一言書く。
3. 企画者がレビューして、問題なければ「Approve」→マージボタンでマージする。
4. マージされたらDay 0の演習は完了。

つまずきやすい点（企画者が机間巡回で見るポイント）：

- `git checkout -b` を忘れてmainのまま作業してしまう → ブランチ名を都度声かけで確認。
- `git push` 時にリモートが無い／認証エラー → 事前準備（0章）でclone・認証が済んでいるか確認。
- PRのターゲットブランチが `main` になっているか確認。
