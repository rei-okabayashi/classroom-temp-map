### 各セクションのメモ

**2. 課題（体感のばらつき）**
- 「同じ教室なのに席によって暑い/寒いと感じたことは？」という問いかけから入ると聞き手を巻き込みやすい。
- ここではまだセンサーの数値は出さない。あくまで“体感”の話にとどめる。

**3. アプローチ（見える化）**
- 体感は人によってズレる → 客観的な数値で複数地点を比較できるようにする、という一段だけの転換を明確に言う。
- 「なぜIoTで／なぜ自作なのか」に軽く触れておくと4章の伏線になる。

**4. システム構成**
- ノード：ESP32-DevKitC-32E＋AE-SHT31（温湿度）。30秒周期でESP-NOWユニキャスト送信。
- 集約：M5Stack Basic。受信してSDカードのCSVに1行ずつ記録、画面にも表示。
- 「なぜESP-NOWか」はここで一言触れておくと、質疑の時間短縮になる（詳細は3章のQ&Aへ）。
- 図は`docs/`配下に既にある構成図があれば流用、なければ発表とりまとめ担当が新規作成。

**5. チーム開発の進め方**
- 未経験メンバーが1人1台のノードを並行して作れた理由＝データ契約（送信フォーマットを最初に固定）とノード用の共通テンプレート（`firmware/node-template/`）。
- Git運用：feature branch → PR → 企画者レビュー → マージ。mainへの直接pushはなし。
- AIルール4つをそのまま紹介：
  1. 共通テンプレートを使う
  2. データ形式の契約を守る
  3. 説明できないコードはマージしない（PR説明欄に自分の言葉で書く）
  4. AIを使った箇所はREADMEに明記する
- 「軽量な進め方を選んだ理由」の言葉の骨子：未経験者中心・実質2週間という制約の中で、重い計画駆動のプロセスより「先に約束事（データ契約・共通テンプレ）だけ固めて、あとは各自が短いサイクルでPRを出す」やり方の方が、詰まった時にすぐ軌道修正できるため。8/21の中間デモを一度合流ポイントとして挟んでいるのも同じ理由。
- 【要確認】このセクションを「アジャイル」という言葉で説明するかどうかはチームで相談（訓練内容と用語がリンクしているかどうかによる）。

**6. 運用データと分析**
- 「○日間」の日数は、実際の運用開始（8/29〜）から発表準備時点までの経過日数で確定する。【要確認】
- 時間帯×場所のクロス集計（例：朝/昼/放課後 × ノード設置地点）をグラフ1〜2枚で見せる。ヒートマップ的な見せ方が向いていそう。
- 生CSVは校正前の値。表示・分析ではデータ契約どおり校正オフセットを適用した値を使う（8/21の並走で決めた値）。
- ノードの設置場所名は学校が特定されない表現にする（「窓際」「廊下側」など役割ベースの言い方に寄せる）。

**7. 改善提案**
- ここは実データが出てからでないと書けない枠。プレースホルダとして「傾向A→提案A」の型だけ用意しておき、8/21・8/28のデータが揃い次第、データ分析担当が中身を詰める。
- 提案は必ず「このデータからこう読み取れる」という根拠とセットにする（感想ベースにしない）。

**8. 学び（KPT）**
- 8/28の完成デモ+KPTで出た内容をそのまま持ってくる想定。今の時点では空欄。

## 2. デモの段取り

### ライブデモ（うまくいく前提の手順）

1. 会場に集約M5Stackとノード最低1台を持ち込み、電源投入。起動〜受信までの待ち時間をあらかじめ計っておく。
2. 画面に気温・湿度・最終受信からの経過秒が表示される様子を見せる。
3. 可能ならその場でノードに軽く息を吹きかける／手で覆うなどして数値が動く様子を見せ、「ちゃんとリアルタイムで反応している」ことを実感してもらう。
4. SDカードを抜いてPCに挿し、`LOG.CSV`の中身をそのまま見せる（生データがある、という安心感を出す）。
5. 時間が許せば、データ分析担当のSQLite集計・グラフ画面を軽く見せる。

### リスクと対策

- 発表会場が普段の教室と違う場合、Wi-Fi環境・電波状況がESP-NOW（チャンネル1固定）に影響する可能性がある。事前に会場で通信テストをしておく。【要確認：会場が確定してから要リハーサル】
- 起動直後は最大30秒（1周期）表示が動かないので、「今データを待っています」と口頭でつなぐ。

### バックアップ運用（ライブが失敗した場合）

- 運用期間中（8/29以降）にM5Stackの画面や実際の動作を**事前に動画で撮影**しておく（スマホでの手持ち撮影で可）。
- ライブデモが不通・機材トラブルの場合は、司会役が「今はこう動いています」と一言添えたうえで即座に録画へ切り替える。切り替えの合図と担当者をチームで事前に決めておく。
- スライドの該当ページに動画をあらかじめ埋め込む／すぐ再生できる状態にしておき、その場で探さない。
- CSVの実データも、スクリーンショットをスライドに保険として仕込んでおく（SDカードの抜き差しが会場で失敗しても止まらないように）。
- 【要確認】バックアップ動画の撮影担当・撮影日をチームで割り振る。

## 3. 想定質問と答えの骨子

| # | 想定質問 | 答えの骨子 |
|---|---|---|
| 1 | なぜESP-NOW？ Wi-Fiじゃダメだったの？ | 学校のWi-Fiに接続する手間や制約がなく、宛先を固定したペアで直接やり取りできるため。個人情報を含まない環境データなので暗号化なしという単純な構成を選べた。 |
| 2 | 精度はどれくらい出るの？ | センサーはSHT31（秋月AE-SHT31）。カタログ上の精度は【要確認：データシート値を発表資料作成前に確認して転記】。CSVには生値を記録し、校正は別途行っている点もあわせて説明。 |
| 3 | 校正はしたの？ | 8/21の中間デモのタイミングで基準となる測定と突き合わせてオフセットを決定。CSV自体は生値のまま残し、表示・分析のときにオフセットを適用する運用（生データを汚さないため）。 |
| 4 | AIに書かせたの？ 自分で作ったと言えるの？ | AIは使ったが、丸投げのコピペではない。共通テンプレート・データ契約という土台を先に決め、各自が自分のPRで「なぜこの実装にしたか」を説明できることをマージ条件にした。AI利用箇所はREADMEに明記している。 |
| 5 | 費用はどれくらいかかった？ | 秋月での部材発注（8/1時点）が¥13,110、別途microSDが約¥900。合計で概算¥14,000程度。【要確認：その後の追加購入があれば反映】 |
| 6 | データはどうやって分析したの？ | M5Stack側でSDカードにCSVをそのまま記録し、訓練で習ったSQLiteを使って集計・分析している。生データと分析結果を分けて扱っている。 |
| 7 | 未経験のメンバーで2週間しかないのに、どうやって分担したの？ | 最初にノード⇔集約間の「データ契約」を固定し、共通テンプレートを用意したことで、各自が自分のノードを並行して作れる状態を作った。8/21に一度中間合流して校正・すり合わせをしている。 |
| 8 | 次に改良するなら何をする？ | 【要確認：チームで合意した上で埋める】想定される方向性としては、M5StackにRTCがなく時刻を手動設定している点の解消、筐体の作り込み、ノード台数の拡張など。 |
