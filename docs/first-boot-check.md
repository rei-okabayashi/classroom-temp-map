# 実機チェックシート — 初回動作確認と日常運用

**対象者**：初回の動作確認（A章）は企画者、8/17週にA章の該当部分を自分のノード（ノードとは、教室に置く測定係の小さなコンピューターです。ESP32というマイコン（＝プログラムで動く小さなコンピューター）と温湿度センサーがセットになっていて、n1〜n4の4台があります）で確認するのはノード担当全員、常設期間中の日常チェック・データ回収（B・C章）は当番になった全員です。
**使い方**：機器が届いたらA章を1台ずつ確認し、8/26以降は教室で最初に画面を見た人がB章の3点を毎日確認します。金曜はC章でデータを回収し、停電のあとはD章、開発中のテスト送信はE章を参照してください。

書き込みとシリアルモニタ（マイコンが出すメッセージをPCの画面で見るための窓です）の基本操作（Arduino IDEでの書き込み手順・シリアルモニタの開き方）は `docs/setup-windows.md` の7章にあるので、ここでは繰り返しません。

---

## A. 初回の動作確認（機器が届いたら1台ずつ）

### A-1. 集約（M5Stack）単体

集約は、4台のノードからデータを受け取ってまとめる係のM5Stackです（M5Stackは画面つきの小型マイコンで、教壇に置いて受信データを表示・記録します）。

1. `firmware/gateway/gateway.ino` を書き込みます（書き込み手順は setup-windows.md 7章「集約担当のみ：M5Stackへの書き込み確認」を参照してください）。
2. シリアルモニタ（115200 baud。baud＝通信速度の設定値です。PC側とボード側で同じ値に合わせます）に次の出力が出ることを確認します。

   ```
   === onmura gateway ===
   MAC: xx:xx:xx:xx:xx:xx
   ```

   （`onmura` は「温度ムラ」をローマ字にした、このプロジェクトの略称です。画面の表示やファイル名など、日本語が使えない場所で使っています。）

3. M5Stackの画面下部にも同じMACアドレス（機器1台ごとに工場出荷時から付いている固有の番号で、機器の住所のようなものです）が表示されることを確認します（画面はラベルが `MAC` 、シリアルは `MAC:` と表記が少し違いますが、アドレスの値は同じです）。SDカードを挿していなければ、画面右下は赤い「SD NG」です。
4. 画面上部に赤字で「JIKOKU MISETTEI  (serial: TIME ...)」という時刻未設定の警告が出ますが、まだTIMEコマンドを送っていないこの時点では**正常**です（A-6で設定します）。

**完了チェック**：シリアルと画面のMACアドレスが一致していればA-1は完了です。このMACアドレスは、あとで各ノードの `config.h` に転記する値なのでメモしておいてください。

### A-2. SDカード

1. FAT32でフォーマットした16GB以下のmicroSDカードを挿し、M5Stackを再起動します（フォーマット手順は tasks-initial.md タスク16を参照してください）。
2. 画面右下が緑の「SD OK」に変わることを確認します。

**うまくいかないとき**：「SD NG」のままなら、カードの抜き差し・再フォーマットを試してください。

### A-3. ノード単体

> **どのファイルを触るかは、時期で変わります。**
> - **企画者が最初に1台だけ動作を見るとき**（機器が届いた直後）は、まだ各自のフォルダが無いので `firmware/node-template/` をそのまま使います。
> - **メンバーが自分のノードを確認するとき**（8/17週以降）は、初期タスク#6〜#9で作った**自分のフォルダ** `firmware/nodes/n1/`（n2〜n4も同様）を使います。**共通の雛形である `node-template` は書き換えません**（4人が同じファイルを書き換えると、あとで必ずぶつかります）。
>
> 以下では、自分のフォルダを `firmware/nodes/n1/` として書きます。企画者の初回確認では `firmware/node-template/` に読み替えてください。

1. `firmware/nodes/n1/config.h` の `NODE_ID` を自分のノードID（`"n1"`〜`"n4"`）に書き換えます。
2. `firmware/nodes/n1/n1.ino` を書き込みます。
3. シリアルモニタに次の出力が出ることを確認します。

   ```
   === onmura node ===
   NODE_ID=n1  schema v1
   my MAC: xx:xx:xx:xx:xx:xx
   ```

4. `GATEWAY_MAC` をまだ `config.h` に転記していない段階では、続けて次の警告が出ますが、これは**正常に動いている証拠**です。

   ```
   !!! 警告: GATEWAY_MAC が未設定(全て0x00)です。
   !!! M5Stackの画面に出るMACを config.h に転記してください。
   ```

**完了チェック**：`=== onmura node ===` と `NODE_ID` 行、`my MAC:` 行が出ていればA-3は完了です。

### A-4. ESP-NOW疎通

ESP-NOW（WiFiルーターなしでESP32どうしが直接データを飛ばせる無線のしくみです）が正しくつながっているかを確認します。

1. A-1で確認した集約のMACアドレスを `config.h` の `GATEWAY_MAC` に1バイトずつ転記し、再書き込みします。
2. 30秒ごとにシリアルモニタへ「send ok : {...}」の行が出て、M5Stackの画面にそのノードの温湿度が表示されることを確認します。

**うまくいかないときの切り分け順（この順で確認してください）**：
① `firmware/node-template/config.h` と `firmware/gateway/config.h` の `WIFI_CHANNEL` が両方とも `1` になっているか確認します（送受で一致している必要があります）。
② `GATEWAY_MAC` の転記を1バイトずつ再確認します（コピーミスがいちばん多い原因です）。
③ シリアルに「add_peer failed. config.h の GATEWAY_MAC を確認してください」が出る場合は、転記の書式（`0x??` 形式・カンマ区切り）を確認します。
④ ①〜③で解決しない場合は、2台の距離を近づける・給電（USBポートやケーブル）を変えて再試行してください。

### A-5. SD記録

1. A-4の状態で数分間受信させます。
2. M5Stackの電源を切り、SDカードをPCで開きます。
3. `LOG.CSV`（カンマ区切りの表形式ファイルで、Excelやスプレッドシートでそのまま開けます）にヘッダ行と受信行が残っていることを確認します。これは1行ごとにフラッシュ（書き込み待ちのデータをその場でSDカードに確定させることです。突然電源が切れても消えないようにするしくみです）されているかどうかの確認です。tasks-initial.md タスク17と同じ内容です。

**完了チェック**：ヘッダ行 `recv_time,clock,node_id,seq,temp_c,hum_pct,status` の下に、受信した分だけ行が並んでいればA-5は完了です（`seq` は通し番号です。送信のたびに1ずつ増え、番号が飛んでいたら途中のデータが消えたと分かります）。

### A-6. 時刻設定

M5Stack本体（Basic/Gray）には、電源オフ時に時刻を保持するハードウェア（RTC）が内蔵されていません。そのため、起動後にPCからシリアル通信を介して現在時刻を送信し、内部時刻を設定する必要があります。

**注意点**
- 時刻の揮発性: 設定した時刻情報は、M5Stackの電源を落とすと消去されます。
- 電源切り替え時のリセット防止: 時刻設定後にPCからシリアルケーブルを抜くと電源が落ち、時刻がリセットされてしまいます。PCから切り離して（スタンドアロンで）時刻を保持したまま動作させたい場合は、下記の手順に従って電源供給を切り替えてください。

**設定に必要なもの**
- M5Stack用スタンディングベース（給電・スタンド用）
- USB Type-Cケーブル × 2本（PC接続用 ×1、外部電源給電用 ×1）
- 外部電源（USB ACアダプターやモバイルバッテリーなど）

**設定手順**

1. PC側でシリアルモニタ（Arduino IDEのシリアルモニタ）を起動します。(Arduino IDEのTools -> Serial Monitorを選択すると、ウィンドウの下部にシリアルモニターが表示されます。)
2. M5StackをPCとUSB接続し、シリアルモニタから次の形式で送信します。

   ```
   TIME 2026-08-17 09:00:00
   ```

   TIMEは、M5Stackの時計を合わせる命令です。「年-月-日 時:分:秒」の形で送ります。

   **送り方（ここでつまずきやすいので、順番どおりに）**：
   1. シリアルモニタの**上部にある入力欄**をクリックします（マイコンからのメッセージが流れてくる欄とは別の、1行だけの入力欄です）。
   2. **入力欄の右にある改行の設定を「New Line」（または「Both NL &amp; CR」）にします。**
      ここが **「No Line Ending」（改行なし）のままだと、送信しても何も起きません**。
      M5Stack側は「行の終わり」の合図を受け取って初めて命令を読み取る作りになっているためです。
      押しても無反応のときは、まずここを疑ってください。
   3. `TIME 2026-08-17 09:00:00` のように入力して、**Enterキー**（または入力欄の右の送信ボタン）を押します。

3. 「clock set OK: <設定後の時刻>」というエコーバックが返るので、**手元の時計と一致しているかを必ず目視で確認します**。
4. 年月日・時分秒のいずれかが範囲外の値だと、時計は変更されずに次のメッセージが返ります。

   ```
   NG: 値が範囲外です。 usage: TIME 2026-08-17 09:00:00
   ```

   この場合は入力し直してください。範囲内での入力ミス（日付を1日間違える等）は時計自体が変わってしまうため、手順2のエコーバックで気づくことが唯一の手がかりです。実在しない日付（例: 2月31日）は自動的に繰り上がった日付（3月3日）として設定されてしまうので、これもエコーバックの目視で確認してください。
5. 設定に成功すると画面上部の赤い警告が消え、時刻表示に変わります。以後の `LOG.CSV` の `clock` 列が `set` になります。
6. エコーバックの時刻が手元の時計と一致し、画面の警告が消えていることを確認します。

**外部電源への切り替え（PCからの切り離し）**
時刻を保持したままPCから切り離すため、以下の順番で操作を行ってください。**順番を間違えると電源が落ち、時刻がリセットされます。**

1. スタンディングベースのUSBポートに2本目のUSBケーブルを接続し、外部電源（ACアダプター等）から給電を開始します。
2. 本体側面に挿さっているPCへのUSBケーブルを静かに抜きます。

**完了チェック**：PCから切り離しても時計が動き、センサーからの情報を取得できているようならA-6は完了です。

## B. 常設期間の毎日チェック（8/26〜）

教室で最初に画面を見た人が、次の3点だけを30秒で確認します。

1. 画面のノード行に赤字で「MUOUTOU」（無応答）が出ていないか。
2. 画面上部に赤字の「JIKOKU MISETTEI  (serial: TIME ...)」が出ていないか。
3. 画面右下が緑の「SD OK」か。

異常があれば、Discordの2行報告に書いてください。

> 例：n3がMUOUTOU 180s、他は正常。SDはOK。

## C. データ回収（金曜・SDカードの安全な抜き差し）

1. **必ずM5Stackの電源を切ってから**SDカードを抜きます。通電中に抜くと以後の記録が止まり、カードを戻しても復帰しません（再起動が必要です）。
2. PCで `LOG.CSV` を、そのPCの `analysis/` フォルダへコピーします（バックアップを兼ねます）。
3. **コピーした `LOG.CSV` を、Discordの進捗報告チャンネルに添付して投稿します。** これがデータ分析担当への受け渡しになります（実測データはリポジトリには入れない決まりなので、Gitでは届きません）。
4. SDカードを戻して電源を入れ、画面右下が「SD OK」になることを目視します（「SD NG」のままなら電源を入れ直してください）。
5. 再起動で時計が消えるため、TIMEコマンドを再送します（手順はA-6を参照してください）。エコーバックの時刻と画面の時刻表示を確認します。

**完了チェック**：`LOG.CSV` が `analysis/` フォルダにコピーされ、**Discordに投稿してデータ分析担当へ渡してあり**、画面が「SD OK」かつ正しい時刻表示になっていればC章は完了です。

## D. 停電・電源断のあと

受信・画面表示・SD記録は、電源が復帰すれば自動的に再開します（手動操作は不要です）。手動で必要になるのは時刻設定だけです。TIMEコマンドの再送手順はA-6を参照してください。

PCやUSBケーブルが教室に無い日に備えて、教壇のM5Stack付近に予備のUSBケーブルを常備しておいてください。

---

## E. テスト送信するときの注意（開発者向け）

手組みのテストパケットを送る場合は、`docs/data-contract.md` のペイロード（1回の送信で運ぶデータの中身です）契約どおりの完全なJSON（「項目名:値」をカンマで並べる、機械が読み間違えないためのデータの書き方です。`v`・`id`・`seq` は必須、正常時は `t`・`h`、異常時は `err`）で送ってください。契約と違う形式のパケットは集約側でdrop（破棄）として数えられ、`LOG.CSV` には記録されません。
