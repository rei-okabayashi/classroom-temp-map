# 実機チェックシート — 初回動作確認と日常運用

**対象者**：初回の動作確認（A章）は企画者、8/17週にA章の該当部分を自分のノードで確認するのはノード担当全員、常設期間中の日常チェック・データ回収（B・C章）は当番になった全員です。
**使い方**：機器が届いたらA章を1台ずつ確認し、8/26以降は教室で最初に画面を見た人がB章の3点を毎日確認します。金曜はC章でデータを回収し、停電のあとはD章、開発中のテスト送信はE章を参照してください。

書き込みとシリアルモニタの基本操作（Arduino IDEでの書き込み手順・シリアルモニタの開き方）は `docs/setup-windows.md` の7章にあるので、ここでは繰り返しません。

---

## A. 初回の動作確認（機器が届いたら1台ずつ）

### A-1. 集約（M5Stack）単体

1. `firmware/gateway/gateway.ino` を書き込む（書き込み手順は setup-windows.md 7章「集約担当のみ：M5Stackへの書き込み確認」を参照）。
2. シリアルモニタ（115200 baud）に次の出力が出ることを確認する。

   ```
   === onmura gateway ===
   MAC: xx:xx:xx:xx:xx:xx
   ```

3. M5Stackの画面下部にも同じMACアドレスが表示されること（画面はラベルが `MAC` 、シリアルは `MAC:` と表記が少し違いますが、アドレスの値は同じです）。SDカードを挿していなければ画面右下は赤い「SD NG」です。
4. 画面上部に赤字で「JIKOKU MISETTEI  (serial: TIME ...)」という時刻未設定の警告が出ますが、まだTIMEコマンドを送っていないこの時点では**正常**です（A-6で設定します）。

**完了チェック**：シリアルと画面のMACアドレスが一致していればA-1は完了です。このMACアドレスは、あとで各ノードの `config.h` に転記する値なのでメモしておいてください。

### A-2. SDカード

1. FAT32でフォーマットした16GB以下のmicroSDカードを挿し、M5Stackを再起動する（フォーマット手順は tasks-initial.md タスク16）。
2. 画面右下が緑の「SD OK」に変わることを確認する。

**うまくいかないとき**：「SD NG」のままなら、カードの抜き差し・再フォーマットを試してください。

### A-3. ノード単体

1. `firmware/node-template/config.h` の `NODE_ID` を自分のノードID（`"n1"`〜`"n4"`）に書き換える。
2. `firmware/node-template/node-template.ino` を書き込む。
3. シリアルモニタに次の出力が出ることを確認する。

   ```
   === onmura node ===
   NODE_ID=n1  schema v1
   my MAC: xx:xx:xx:xx:xx:xx
   ```

4. `GATEWAY_MAC` をまだ `config.h` に転記していない段階では、続けて次の警告が出ますが、これは**正常に動いている証拠**です。

   ```
   !!! 警告: GATEWAY_MAC が未設定(全て0x00)です。
   !!! M5Stackの画面に出るMACを config.h に転記してください。
   ```

**完了チェック**：`=== onmura node ===` と `NODE_ID` 行、`my MAC:` 行が出ていればA-3は完了です。

### A-4. ESP-NOW疎通

1. A-1で確認した集約のMACアドレスを `config.h` の `GATEWAY_MAC` に1バイトずつ転記し、再書き込みする。
2. 30秒ごとにシリアルモニタへ「send ok : {...}」の行が出て、M5Stackの画面にそのノードの温湿度が表示されることを確認する。

**うまくいかないときの切り分け順（この順で確認する）**：
① `firmware/node-template/config.h` と `firmware/gateway/config.h` の `WIFI_CHANNEL` が両方とも `1` になっているか確認する（送受で一致必須）。
② `GATEWAY_MAC` の転記を1バイトずつ再確認する（コピーミスが最多の原因）。
③ シリアルに「add_peer failed. config.h の GATEWAY_MAC を確認してください」が出る場合は、転記の書式（`0x??` 形式・カンマ区切り）を確認する。
④ ①〜③で解決しない場合は、2台の距離を近づける・給電（USBポートやケーブル）を変えて再試行する。

### A-5. SD記録

1. A-4の状態で数分間受信させる。
2. M5Stackの電源を切り、SDカードをPCで開く。
3. `LOG.CSV` にヘッダ行と受信行が残っていることを確認する（1行ごとにフラッシュされているかの確認。tasks-initial.md タスク17と同じ）。

**完了チェック**：ヘッダ行 `recv_time,clock,node_id,seq,temp_c,hum_pct,status` の下に、受信した分だけ行が並んでいればA-5は完了です。

### A-6. 時刻設定

1. M5StackをPCとUSB接続し、シリアルモニタから次の形式で送信する。

   ```
   TIME 2026-08-17 09:00:00
   ```

2. 「clock set OK: <設定後の時刻>」というエコーバックが返るので、**手元の時計と一致しているかを必ず目視で確認します**。
3. 年月日・時分秒のいずれかが範囲外の値だと、時計は変更されずに次のメッセージが返ります。

   ```
   NG: 値が範囲外です。 usage: TIME 2026-08-17 09:00:00
   ```

   この場合は入力し直してください。範囲内での入力ミス（日付を1日間違える等）は時計自体が変わってしまうため、手順2のエコーバックで気づくことが唯一の手がかりです。実在しない日付（例: 2月31日）は自動的に繰り上がった日付（3月3日）として設定されてしまうので、これもエコーバックの目視で確認してください。
4. 設定に成功すると画面上部の赤い警告が消え、時刻表示に変わります。以後の `LOG.CSV` の `clock` 列が `set` になります。

**完了チェック**：エコーバックの時刻が手元の時計と一致し、画面の警告が消えていればA-6は完了です。

## B. 常設期間の毎日チェック（8/26〜）

教室で最初に画面を見た人が、次の3点だけを30秒で確認します。

1. 画面のノード行に赤字で「MUOUTOU」（無応答）が出ていないか。
2. 画面上部に赤字の「JIKOKU MISETTEI  (serial: TIME ...)」が出ていないか。
3. 画面右下が緑の「SD OK」か。

異常があれば、Discordの2行報告に書いてください。

> 例：n3がMUOUTOU 180s、他は正常。SDはOK。

---

## C. データ回収（金曜・SDカードの安全な抜き差し）

1. **必ずM5Stackの電源を切ってから**SDカードを抜く。通電中に抜くと以後の記録が止まり、カードを戻しても復帰しません（再起動が必要です）。
2. PCで `LOG.CSV` を `analysis/` フォルダへコピーする。
3. SDカードを戻して電源を入れ、画面右下が「SD OK」になることを目視する（「SD NG」のままなら電源を入れ直す）。
4. 再起動で時計が消えるため、TIMEコマンドを再送する（手順はA-6を参照）。エコーバックの時刻と画面の時刻表示を確認する。

**完了チェック**：`LOG.CSV` が `analysis/` フォルダにコピーされ、画面が「SD OK」かつ正しい時刻表示になっていればC章は完了です。

---

## D. 停電・電源断のあと

受信・画面表示・SD記録は、電源が復帰すれば自動的に再開します（手動操作は不要です）。手動で必要になるのは時刻設定だけです。TIMEコマンドの再送手順はA-6を参照してください。

PCやUSBケーブルが教室に無い日に備えて、教壇のM5Stack付近に予備のUSBケーブルを常備しておいてください。

---

## E. テスト送信するときの注意（開発者向け）

手組みのテストパケットを送る場合は、`docs/data-contract.md` のペイロード契約どおりの完全なJSON（`v`・`id`・`seq` は必須、正常時は `t`・`h`、異常時は `err`）で送ってください。契約と違う形式のパケットは集約側でdrop（破棄）として数えられ、`LOG.CSV` には記録されません。

困ったときは、自己判断で強引に進めず、企画者に状況を伝えて相談してください。
