# analysis — 運用データの分析（データ分析担当の作業場所）

SDカードにたまった実測データを読み込んで、「いつ・どこが暑いか」を数字で出す場所です。
このプロジェクトの成果物（発表で見せるもの）は、ここから作ります。

---

## 0. 準備：Pythonを入れる（最初に1回だけ）

`log_to_sqlite.py` は **Python** というプログラムで動きます。入っていないPCでは動かないので、先に入れてください。

1. [https://www.python.org/downloads/windows/](https://www.python.org/downloads/windows/) を開き、Windows installer (64-bit) をダウンロードします。
2. ダウンロードした `.exe` を実行します。**最初の画面で「Add python.exe to PATH」のチェックを必ず入れてください**（ここを忘れると、次の手順で `python` と打っても認識されません）。
3. 「Install Now」を押します。
4. **開いていたターミナルはいったん閉じて、開き直します**（開きっぱなしの画面には設定の変更が反映されません）。
5. ターミナルで `python --version` と入力してEnterを押し、`Python 3.x.x` のように表示されれば準備完了です。

> **うまくいかないとき**
> - Microsoft Storeの画面が開いてしまう → 手順2の「Add python.exe to PATH」のチェックが入っていません。インストーラをもう一度実行して入れ直してください。
> - それでも認識されない → PCを再起動してから、もう一度 `python --version` を試してください。
> - どうしても入らない → 企画者に連絡してください。**Excelでも同じ集計はできます**（下の「Pythonが使えないとき」を参照）。

**追加のライブラリは要りません。** `log_to_sqlite.py` はPythonに最初から入っている機能だけで動きます。

## 1. まずはサンプルで動かしてみる（実データが無くてもできます）

実測データが集まるのは8/26以降です。それまでに、**ダミーデータで一度動かしておく**と本番で慌てません。

1. VSCodeでこのリポジトリ（`classroom-temp-map` フォルダ）を開きます。
2. メニューの `ターミナル`（Terminal）→ `新しいターミナル`（New Terminal）を開きます。
3. `analysis` フォルダへ移動します。

   ```
   cd analysis
   ```

4. サンプルデータで実行します。

   ```
   python log_to_sqlite.py sample/LOG.CSV
   ```

うまくいけば、ノード別のまとめと「時間帯 × ノードの平均気温」の表が画面に出ます。
**この表の一番右の「最大差」の列が、私たちが測ろうとしている「温度ムラ」そのものです。**

## 2. 本番：実測データで動かす

1. **回収したLOG.CSVを受け取ります。** 金曜のデータ回収のあと、回収した人が Discord の進捗報告チャンネルに `LOG.CSV` を添付します。それをダウンロードして、この `analysis` フォルダに置いてください（回収の手順は [docs/first-boot-check.md](../docs/first-boot-check.md) のC章）。
2. `analysis` フォルダにいることを確認して、実行します。

   ```
   python log_to_sqlite.py LOG.CSV
   ```

3. 画面に出た表を保存します。スクリーンショットでもよいですし、次のようにファイルへ書き出すこともできます。

   ```
   python log_to_sqlite.py LOG.CSV > result.txt
   ```

このコマンドは `LOG.CSV` を読み込み、SQLiteのデータベースファイル `onmura.db` を作ります（`onmura` は「温度ムラ」をローマ字にした、このプロジェクトの略称です）。

- `onmura.db`（SQLite。ファイル1つで使える小さなデータベースです。訓練校で学習済み）が作られ、ノード（教室に置く測定係の小さなコンピューターです）別サマリと「時間帯×ノードの平均気温」クロス表が表示されます
- **最大差の列が「温度ムラ」そのものです** — 発表の根拠データはここから作ります
- 訓練で習ったSQLiteの実践場所です。`sqlite3 onmura.db`（作られたデータベースを開いて、自分で集計を試すためのコマンドです）で開いて自由に集計してかまいません

時刻未設定（clock=unset）の行とセンサーエラー行は自動で除外されます（`--include-unset` で含められます）。
また、同じデータが2回記録されていた分（電波が届かず再送されたとき）も自動で1件にまとめられます。

## 3. どこまでやれば「できた」か

| 段階 | 中身 | 判定 |
|---|---|---|
| **最低限** | 上のクロス表と「最大差」の列＋グラフ1枚 | **これで発表に使えます** |
| 余裕があれば | 日別・曜日別の集計を足す | 拡張 |
| さらに | 設置場所ラベル（READMEのn1〜n4対応表）と結合して「窓際 vs 廊下側」で語る | 拡張 |

グラフを何で作るか（表計算ソフトか、Pythonのグラフ機能か）は、**1週目のうちに企画者と相談して決めます**。
どちらでも構いませんが、Pythonのグラフ機能（matplotlib）を使う場合は `pip install matplotlib` の追加インストールが必要になるので、早めに決めておくと安心です。

> 発表のグラフでは、`n1`〜`n4` という名前を「窓際」「廊下側」のような言い方に置き換えます（公開リポジトリなので、学校や教室が特定される表現を避けるためです）。集計をやり直す必要はなく、見出しの言い換えだけです。

## 4. Pythonが使えないとき（Excel・スプレッドシートで同じことをする）

`LOG.CSV` はただのCSVなので、ExcelやGoogleスプレッドシートで開いてピボットテーブルを作れば、同じクロス表が作れます。
ただし、**スクリプトが自動でやっている「除外」を手でやる必要があります。** ここを飛ばすと、気づかないまま平均がおかしくなります。

1. `clock` 列が `set` 以外（`unset`）の行を消します（停電などで時計が未設定だった間の行で、時刻が当てになりません）
2. `status` 列が `ok` 以外（`sensor_err`）の行を消します（気温が空欄の行です）
3. 同じ `node_id` で `seq` が直前の行と同じものがあれば、片方を消します（再送で二重に記録された分です）
4. `recv_time` の列を、日付・時刻として認識させます（列を選んで「セルの書式設定」から変更します）
5. ピボットテーブルで `recv_time` を右クリック →「グループ化」→ **「時」だけにチェック**を入れます

手数が多いので、Excelに切り替えると決めたときは企画者に声をかけてください。**除外まで済ませたシートを一度作って渡します。**



## グラフ描画プログラムについて
- 今回の折れ線グラフ及びヒートマップはpythonのライブラリであるpandasとmatplotlibを使用しています。
- pandasはデータフレームという二次元の表形式でデータを管理し、効率的に集計や分析ができるライブラリです。
- matplotlibは手軽に二次元や三次元のグラフを描画できるライブラリです。ご自身でプログラムを実行し、
- グラフを出力したい場合pythonの環境とpandas,matplotlibのインストールが必要になります。

pythonがすでにpcに入っている場合、コマンドプロンプトなどで

```cmd
pip install pandas
```
でpandasを
```cmd
pip install matplotlib
```
を実行することでインストールできます。


## 折れ線グラフ使用方法　"data_analysispra.py"
1, "data_analysispra.py"は上記で作成したonmura.dbを取り込みます。注意点はonmura.dbとdata_analysispra.pyを同じフォルダに配置することです。
2, df = pd.read_sqlから始まる行の時間範囲(recv_time)を変えればグラフの範囲が変わりますが、データベース内の時間範囲と一致していない場合、グラフが想定よりも短かったり、エラーメッセージが表示されてしまいます。
3, 実行を押すとグラフが表示されます。
4, プログラムの下側plt.show()の手前にコメントアウトしてある行がありますが、これは指定した時間の値を出力させる確認用のものです。気になったらお使いください。
5, 全ノードを一括に表示する"data_multibar.py"も基本的に使い方は同じですが、時間範囲をノードごとに設定しなければならないので、注意が必要です。


## ヒートマップ使用方法 "heatmap_temp.py"
onmura.dbからノード名、温度、時間を時間順に取得します。時間範囲の設定は折れ線グラフの時と同様です。
他に変更できる箇所は、freqT = ""とcmap=""の部分です。freqTは表示されるグラフのマス目の幅を指定する変数で"20min","1hour"などのように時間を入れてください。cmapはグラデーションの指定です。ネット検索でもグラデーション名を探せますが、redやblueなど適当に色名を入れるとエラーメッセージに近いグラデーション名を書いてくれるので、それを入力しましょう。
